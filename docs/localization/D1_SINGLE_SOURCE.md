# Единый центр переводов: Modern и Cloudflare D1

## Приоритет значений (RU / EN / JP / TW)

1. Опубликованное значение **локализации D1** (таблица `localization_overrides`) при наличии записи с текстом.
2. Предыдущие публикации в D1: `ui_translation_overrides`, `result_label_overrides` и тексты опубликованного каталога.
3. Утверждённые исходные тексты проекта (`localization/*`) как начальная база и безопасный fallback.

**Клиент не исправляет формулировки из D1 по собственным словарям.** Если опубликовано длинное название, оно показывается как есть, пока новая версия не опубликована из админки или через проверенную миграцию D1. Смена регистра, исправление орфографии или сокращение — это **правка перевода**, не CSS-операция.

Пустая запись `localization_overrides` (версионированный сброс) означает возврат к исходному базовому значению и **не должна** возрождать старую публикацию. Все правки переводов используют проверки версий, а массовые изменения — ещё и сравнение ожидаемого предыдущего текста.

## Один владелец у каждого типа записи

- **Интерфейс (UI)**: `localization/ui.en.json` задаёт список редактируемых ключей, но не заменяет опубликованные значения D1. Заголовки, кнопки, подсказки и ARIA-подписи должны привязываться к `i18n.t/bindText/bindAttribute` по устойчивому ключу.
- **Термины игры (game)**: каталог ключей из `game-terms.ru.json`; выдача через `i18n.game`. Никаких дополнительных browser-only переименований опубликованных D1-значений.
- **Гильдия, Честь**: отдельные ключи у каждого умения и уровня. Утверждённые файлы — fallback. D1 — приоритетное опубликованное значение.
- **Новые предметы, души и навыки каталога**: *тексты и механика остаются в одном документе каталога D1*. Редактор переводов отображает их для поиска, но переходит в карточку каталога — не создаёт дубликат `localization_overrides` поверх неё.
- **Legacy**: сохранённый исходный калькулятор и музей; данный контракт относится к Modern. Данные расчётов и числовые правила не являются переводами.

## Админка

Путь: «Переводы · единый центр». Выбери категорию и текстовый ключ. Кнопка «Сравнить RU / EN / JP / TW» показывает эффективные опубликованные значения, наличие перевода и его происхождение по четырём языкам. Из сравнения можно перейти к нужному языку; запись и перевод идентифицируются теми же `scope + id + locale`.

Существующие возможности сохранены: поиск, фильтрация пропущенных переводов, черновики в D1, история, пакетная публикация с предпросмотром, проверка конфликтов и восстановление исходного текста. Никаких Excel-файлов в штатном редактировании не требуется.

## Безопасная миграция прежних сокращений

`0012_localization_resistance_d1.sql` исправляет ровно пять **точно совпавших** устаревших русских публикаций: обновляет существующие D1-переводы либо создаёт отдельные версии переводов поверх старого опубликованного каталожного имени. Каталог и игровая механика остаются неизменны; версия изменённой строки повышается, а история изменения сохраняется. Если версия уже пользовательская, текст отличается от известного старого варианта либо существует неопубликованный черновик, исправление **не применяется автоматически**. Дополнительно версия добавляет два новых перевода информационных строк о релизах. Остальные языки, каталог и формулы не трогаются.

## Проверка полноты

Не надо путать существование ключа с реальной привязкой элемента к нему. Перед добавлением очередного текста следует проверить:
1. У текста есть стабильный ключ в реестре UI, game или единственном каталожном документе.
2. Все четыре языка видны в центре переводов, а отсутствующие значения отмечены как fallback, не как готовый перевод.
3. Смена языка и публикация нового значения обновляют отображение без изменения сборки и численных характеристик.
4. Результат согласуется с пользовательскими черновиками, версионированным сбросом и историей.
5. Проверка учитывает названия, описания, подсказки, ARIA/placeholder, сообщения об ошибках, пустые состояния и динамический текст.

**Ограничение:** реестр охватывает ключи Modern и записи каталога; произвольные текстовые литералы, старые Legacy-внутренности, новые неразмеченные тексты и содержание версионного `CHANGELOG` не становятся редактируемыми автоматически. Для них требуется выделить ключ и добавить привязку, а для новых каталожных записей использовать карточку каталога. Нельзя честно считать такой аудит полностью завершённым без проверки каждого экрана и динамического сценария.
