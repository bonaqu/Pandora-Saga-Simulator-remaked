# Проверка входных данных лечения — 12.10.2026

## Назначение

Документ технический. Игровые расчёты Modern должны учитывать не только описание зелья, но и класс, максимальный LP, итоговую STA, пассивки, мастерство ближнего боя, экипировку, души, усиления, выбранные заклинания и порядок округлений. Совпадение Modern с замороженным Legacy 2.00 не доказывает совпадения с актуальным игровым клиентом.

**Датированные источники для воспроизведения:** коэффициенты 28 классов за 2026-10-11, данные items/Souls за 2026-10-07. Файлы нельзя считать снимком на сегодняшний день без отдельной успешной загрузки.

## Проверяемая формула зелья 15% в сохранённом движке

```js
POT = 100 + Math.floor(STA * STA / 500)
  + (humanPharmacyPassive ? 15 : 0)
  + (warriorBranch && level >= 12
      ? Math.floor((meleeMasteryA + meleeMasteryB) / 10) * 10 : 0)
  + knownFlagsAndEquipmentBonuses;
heal = Math.floor(LP * Math.ceil(15 * POT) / 10000);
```

Формула дословно повторяет порядок операций `js/calc.js` для `POT` и процентного восстановления. *Не переносить эту формулу на текущий игровой клиент без независимой проверки.* Вызовы `LP` и `STA` должны учитывать правильный порядок применения всех подтверждённых эффектов.

«Улучшение лечения» — пассивка воинской ветки с 12-го уровня (`Skill[0][0][1]`), которая добавляет `10 × floor(сумма двух составляющих ближнего боя / 10)` к `POT`. Это не `EP_CAST_HEAL_LIFE_SCALE` и не бонус лечебным заклинаниям. Для 101 ближнего боя — +100 POT, не +101.

Изолированный пример: паладин, `LP=9300`, `POT=200` → `2790` ОЗ от базового зелья 15%; монах, `LP=7000`, `POT=100` → `1050` ОЗ. Прибавки от STA, расы, вещей и душ исключены. Практическое количество восстановленного ОЗ, ограничения слотов и эффекты клиента независимо не подтверждены.

## Уже установленные различия

Предыдущая проверка `docs/CALCULATION_PARITY_AUDIT_2026-10-11.md` документирует различия коэффициентов HP/MP у всех 28 классов между архивным движком и справочником нового сервера. **Менять только константы без проверки формулы и порядка округления нельзя.** Особенно для процентных зелий, у которых ошибка в максимальном LP немедленно превращается в ошибку лечения.

Датированный снимок содержит `103018` «Душа зелий» с `EP_MASTERY_POTION a=8`, а предмет `50061` «Таинственное зелье» с `EP_HEAL_LIFE a=145` и `EP_HEAL_MANA a=75`. Историческая подсказка 175 ОЗ в Legacy не является актуальным числовым эталоном. Не перезаписывать пользовательские D1-переводы автоматически.

## Исполнимый аудит текущего источника

```bash
node scripts/audit_pandora_os_live_healing_inputs.mjs --json
node scripts/audit_current_skill_source.mjs --output /tmp/current-skill-report.json
```

Первый скрипт читает три JSON-реестра (28 классов, предметы, души) в GET-only режиме и сравнивает дату снимка с полученным свежим источником. Он проверяет идентичности, поля экипировки, классовые ограничения и эффекты предметов, потенциально связанные с STA, LP и лечением. Показывает изменения, отсутствия и новые релевантные записи; изменения описания/названия не считаются изменениями расчётов. Данные не публикуются в D1. При невозможности загрузить источник скрипт **завершается ошибкой и не использует старый снимок как «live»**.

Второй скрипт выполняет независимую инвентаризацию доступных навыков и их вариантов: класс/уровень/ветка/требования/стоимость/тайминги, если это подтверждено опубликованными игровыми данными. Он не утверждает, что серверный JSON показывает реализацию пассивных механик в клиенте. Он не изменяет каталоги и сохранения.

Режим локального повтора (без сети): разместить `classes.json`, `items.json`, `souls.json` в каталоге и запустить:

```bash
node scripts/audit_pandora_os_live_healing_inputs.mjs --source-dir /path/to/registry --json
node scripts/audit_pandora_os_live_healing_inputs.mjs --source-dir /path/to/registry --strict
```

**Ограничения:** подбор «похожих» ID, точные игровые ограничения экипировки, допустимость всех комбинаций душ, баффы, пассивные эффекты, поведение HP после переполнения, формулы реального клиента и смена ревизии опубликованных билдов не входят в доказанную область. Живые source drift результаты должны рассматриваться отдельно и только потом превращаться в версионированные, протестированные изменения Modern.

## Политика публикаций

- Замороженный Legacy 2.00, D1 и уже сохранённые билды не изменять аудитом.
- Не переносить неоднозначные эффекты или округления в Modern догадкой.
- Публикуемые в «Что нового» сообщения описывают только пользовательские изменения; ссылки на игровой API, названия технических файлов и источник данных остаются за пределами changelog.
