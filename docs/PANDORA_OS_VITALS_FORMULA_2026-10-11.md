# Подтверждённая формула HP/MP Pandora Saga OS — 2026-10-11

**Статус:** получено прямое подтверждение исходной формулы действующего
публичного калькулятора. Подготовлены повторяемые математические тесты,
но значения Modern **не заменены** до проверки соответствия бонусов,
публикуемых D1 классов и сохранённых сборок. Это технический протокол, а
не завершённая миграция игровой механики.

## Непосредственно проверенный источник

- Исходные коэффициенты 28 классов: https://pandorasaga-os.com/gamedata/classes.json .
- Актуальный на момент проверки вычислительный JS:
  https://pandorasaga-os.com/assets/BuildCalculator-BiybySwQ.js .
- Подтверждены фрагменты `ga(e,a,t)` (атрибуты и HP/MP),
  `F(e)` (округление до ближайшего целого, 0.5 к чётному) и
  `fa(e,a)` (модификаторы экипировки).
- Снимок только 28 HP/MP коэффициентов находится в
  `tests/fixtures/pandora-os-classes-20261011.json`.
  Дата файла важна: в будущем сервер может изменить коэффициенты.

Исходная формула после применения модификаторов характеристик:

```text
effectiveSTA = max(1, baseSTA + flatSTA + floor(baseSTA * staPercent / 100))
effectiveSPR = max(1, baseSPR + flatSPR + floor(baseSPR * sprPercent / 100))

HP = roundHalfToEven(effectiveSTA * class.hp.vit
                   + level * class.hp.lv + class.hp.base)
     + maxLifeConst
MP = roundHalfToEven(effectiveSPR * class.mp.spi
                   + level * class.mp.lv + class.mp.base)
     + maxManaConst
```

`baseSTA` и `baseSPR` определяются не только введёнными очками: на
сервере они собираются из стартовых параметров выбранной расы, стартовых
параметров базового класса и распределения персонажа. Внутренние
характеристики класса и числовые модификаторы навыков учитываются в этой
проверке **только в пределах отображённой формулы** — другие статусы и
условные игровые эффекты требуют собственной сверки.

При ровно `162.5` результат `162`, при `163.5` — `164`. Это
не `Math.ceil` и не стандартный `Math.round` JavaScript.

### Независимый вектор

Для коэффициентов `GLADIATOR`, уровня 45, STA 7 и SPR 4:

```text
HP = roundHalfToEven(7 * 11.82 + 45 * 31.35 + 150)
   = roundHalfToEven(1643.49) = 1643
MP = roundHalfToEven(4 * 2.53 + 45 * 2.73 + 30)
   = roundHalfToEven(162.97) = 163
```

Эта пара совпадает с наблюдавшимися на странице числами, но один HTML-экран
**не доказывает**, какой класс был активен в состоянии клиентского JS.
Поэтому этот вектор является корректной проверкой функции по опубликованным
коэффициентам, но не полным подтверждением состояния чужого персонажа.

## Почему нельзя просто заменить Status.Mod

- Текущий Legacy в `js/calc.js` делает два `Math.ceil`, причём
  множитель STA/SPR округляется **до** умножения. Это не эквивалентно
  формуле сервера даже при обратных коэффициентах `100/x`.
- Все 28 записей опубликованного каталога классов по-прежнему используют
  тот же исторический шестичисловой формат. Для Current нужна новая
  версионированная схема коэффициентов `base/lv/vit/spi` с проверяемой
  связью с D1, иначе изменения классов через админку начнут неявно
  игнорироваться.
- Дополнительные `LP`/`MP`-бонусы в Legacy (гильдия, баффы, процентная
  экипировка) должны быть проверены на live-сервере независимо. Без этого
  нельзя обещать полностью совпадающие итоговые HP/MP.

## Статусы дальности оружия

В сохранённом `js/calc.js` ветки `RangeMelee` (индекс 40) и
`RangeRange` (индекс 41) принудительно показывают `---`, несмотря
на частичную обработку опций. В современном JS сервера доступно поле
`weapon.range` у конкретного оружия; там же различается `kind`.
Поле `weapon.range` не следует превращать в общее числовое значение для
всех предметов либо принимать за дальность каждой умелки без проверки
правил игры. Следующий шаг — сопоставить из live-каталога оружие по
стабильному ID и слотам, записать правила дальности и бонусов, сравнить
векторы до публикации. Пока невалидированные значения остаются `---`.

## Условия включения Modern-расчётов

Сначала связать новые коэффициенты с версионированным редактируемым
каталогом D1, подтвердить независимым набором эталонных классов,
рас, умений, экипировки/душ и баффов точные итоги, затем перейти на
новый Modern расчёт. Legacy, его HTML и массивы останутся нетронуты.
