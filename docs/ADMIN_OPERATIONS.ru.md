# Админка Modern: эксплуатация и восстановление

Статус: авторизация, редактор экипировки/душ и первые редакторы классов,
расовых, активных и пассивных навыков развёрнуты и проверены на настоящем Worker.
Пасхалка и потребитель нового каталога на основном сайте ещё не опубликованы.
Расширение механик редактора остаётся в разработке. Не считайте эту страницу
подтверждением завершения Modern 3.00.

Текущий проверенный Worker: `c488e6d9-9403-4285-94e0-37b427a72888`.
Миграции 0001 и 0002 применены; публичный каталог остаётся revision 0.
Тестовые предметы и выдуманные характеристики в production не публиковались.

## Где хранятся данные

- Публичный сайт: GitHub Pages, без паролей и секретов.
- Админка и API: `pandora-saga-simulator-remaked-admin-api.bonaqu.workers.dev`.
- База: D1 `pandora-saga-simulator-remaked-admin-db`, binding `DB`.
- Один логин: `admin`. Пароль генерируется случайно и сохраняется только в
  личном файле вне репозитория: `D:\CODEX\Private\PandoraSagaSimulator\admin-login.txt`.
  Не загружайте этот файл на GitHub. На Windows у каталога отключается
  наследование доступа, доступ выдаётся текущему пользователю и SYSTEM.
- В D1 хранится соль и хеш пароля, не пароль; pepper — только в Cloudflare
  Secrets (`AUTH_PEPPER`). Сессии представлены хешами случайных токенов.
- Cookie: HttpOnly, Secure, SameSite=Lax, без Domain, путь `/`. В браузерных
  хранилищах нет auth-токенов. Вход открывает first-party страницу Worker;
  third-party cookies между GitHub Pages и workers.dev не требуются.

## Как войти (после публикации всей функции)

1. Откройте основной сайт. Кликните вне поля поиска или другого поля ввода.
2. В английской раскладке наберите `IDDQD`. Не нужно удерживать клавиши.
3. После сообщения `IDDQD ACCEPTED` введите логин и пароль из личного файла.
4. Откроется защищённая консоль на домене Worker. Успешный вход:
   `GOD MODE ENABLED / WELCOME, ADMIN`.
5. Закончив, нажмите `LOGOUT`. Сообщение: `GOD MODE DISABLED`.

Код IDDQD только открывает интерфейс. Он не предоставляет права доступа.
Адрес админки можно открыть напрямую: безопасность от скрытого адреса не зависит.

## Серверные правила

- Сессия действует не более 8 часов; после 30 минут без обращения к серверу
  нужно войти снова. Каждая приватная операция проверяет D1-сессию.
- Изменения требуют точного origin админки и CSRF-токена в заголовке.
- Login: не более 5 попыток/IP за минуту и 30 общих попыток за 15 минут.
  IP не записываются открытым текстом. Блокировка сама истекает; постоянного
  lockout аккаунта нет.
- Запросы ограничены по размеру; API использует параметризованные SQL.
- CORS разрешает только `https://bonaqu.github.io`, без wildcard и передачи
  credential-cookie в cross-origin JS.
- Пароль: scrypt, N=16384, r=8, p=5, 32-байтная соль и отдельный HMAC-pepper.
  Эта конфигурация указана в [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html#scrypt).
  Native Node crypto поддерживается [Cloudflare Workers](https://developers.cloudflare.com/workers/runtime-apis/nodejs/crypto/).
  PBKDF2/600000 проверен на Cloudflare и отклоняется лимитом 100000; защита
  не была снижена до этого лимита. Production-вход подтверждён на версии
  `9e4a3266-46ee-4a51-ad8d-525bd62e0a74`, включая переход с GitHub Pages при
  блокировке сторонних cookies, CSRF-отказ и отзыв сессии после выхода.

## Каталог (в разработке)

Что доступно в проверенном редакторе:

| Раздел | Что можно менять | Что учитывает симулятор |
| --- | --- | --- |
| Экипировка / оружие | Исходные вещи и новые варианты: названия, описание, тип нового варианта, уровень, слоты, ограничения и числовые эффекты | Исходный расчёт экипировки, улучшений и вставленных Souls |
| Souls / души | Исходные и новые души: названия, описание, приставка, допустимые слоты и эффекты | Бонусы только вставленной совместимой души |
| Классы персонажей | 28 существующих классов: названия, описание, шесть параметров LP/MP | Рост LP/MP через исходные формулы; новые классы и лимиты веток пока недоступны |
| Активные навыки | 178 существующих навыков: названия, описание, MP, применение, перезарядка и длительность | Данные реально изученных умений; симуляции боевого урона в движке нет |
| Пассивные навыки | 33 существующих навыка: названия, описание, дополнительные бонусы и условия оружия, щита, езды | Бонус только изученного навыка при выполнении условий; исходная пассивка сохраняется |
| Расовые пассивки | 18 существующих способностей: названия, описание, сохранение/добавление/замена числового эффекта | Эффект выбранной способности; исходный бонус не удваивается при замене |

Названия и описания во всех разделах можно задавать на EN/RU/JP/TW. Редактор
не разрешает произвольный код. Правка текста не создаёт отсутствующую игровую
механику. Таблица описывает уже проверенные возможности, а не обещания будущих.

Legacy 2.00 остаётся неизменным. Админка читает его 1120 вещей и 184 души как
исходный каталог; публикации хранятся отдельно в D1. Черновик не виден игрокам.
Публикация получает номер версии, а восстановление старой версии создаёт новую:
история и старые номера не удаляются. Сохранение и публикация проверяют версии,
чтобы две открытые вкладки не перезаписали друг друга.

Названия, описания, уровень, число слотов (0–3), доступные расы/классы и числовые
эффекты редактируются отдельно. Правка только названия сохраняет исходные
Legacy-эффекты. Поддерживаемые числа переводятся в формат данных движка, а не
в новые формулы. Сложные специальные эффекты исходника нельзя писать произвольным
кодом. Тип уже созданной вещи связан с ID в сохранённых билдах: для другого типа
нужно создать вариант с новым ID, а не переопределять старый ID.

В утверждённую задачу также входят классы, навыки, пассивные и расовые способности.
Локально уже проверен первый редактор 28 существующих классов: названия на четырёх
языках, описание и шесть исходных параметров LP/MP. Первые два — базовые значения;
остальные четыре — делители роста от уровня и STA/SPR, не прямые прибавки.
Нулевой делитель запрещён. Изменения проходят через существующие формулы движка
и сохраняются вместе с версией билда. Новые классы, лимиты веток и встроенные
пассивки пока не редактируются: смена названия не создаёт новую механику.
Этот блок развёрнут на Worker, но не опубликован на Pages.
Также локально готов редактор 18 существующих расовых пассивок. У него три режима:
«Сохранить» меняет только текст, «Добавить» оставляет исходный эффект и прибавляет
заданные бонусы, «Заменить» отключает исходный расчётный эффект и применяет только
заданные числа. Пустая замена убирает расчётный эффект. Способность действует
только при выборе её персонажем. Произвольные боевые действия и код не разрешены.
Проверены все 18 исходных результатов, отсутствие двойного бонуса и восстановление
версии при загрузке билда. Этот редактор развёрнут на Worker.
Первый редактор экипировки/Souls не означает завершения всей админки. Поддерживаемые
числовые параметры уже передаются в исходный расчёт; расширение условных эффектов
требует отдельной проверки Legacy engine. Неподдерживаемая механика должна быть явно
обозначена, а не имитироваться изменением названия или описания.

Локально проверен первый редактор 178 активных и 33 пассивных навыков. У активных
можно менять текст, MP и время применения/перезарядки/длительности: это значения
в штатном списке изученных умений, не новая симуляция боя. У пассивных можно
добавлять числовые бонусы и условия оружия, щита и верховой езды. Изучение проверяет
сам исходный движок, даже когда список умений скрыт. Исходные требования и тип
навыка пока сохраняются. Замена встроенных классовых пассивок и новые навыки ещё
не реализованы. Этот блок развёрнут на Worker. Реальный авторизованный просмотр
всех четырёх новых редакторов на ПК и телефоне проверен без создания черновиков
или публикации тестовых данных. В source-каталоге всего 1561 запись.

Локальный Modern-код с суффиксом контекста C1 теперь переносит верховую езду,
включённые эффекты, Honor, бонусы клана и три параметра персонажа-кастера.
Старые CSV/сжатые коды по-прежнему читаются, но не содержат этих настроек:
Modern загружает их с исходными выключенными эффектами. Новый код предназначен
для Modern; museum Legacy его не читает. Полная публикация на Pages ещё впереди.

## Как применяются опубликованные изменения к билдам

После выпуска Modern 3.00 новые посетители получат опубликованный каталог.
Существующий билд останется на своей ревизии: правка вещи в админке не должна
незаметно менять результат сохранённого или присланного билда.

В «Билды» показана ревизия текущего персонажа и есть «Обновить текущий билд».
Кнопка проверяет настоящий публичный каталог через интернет. Офлайн-кэш
позволяет открыть ранее загруженный билд, но не считается свежим обновлением.
Успешное обновление оставляет экипировку, вставленные Souls, навыки, баффы,
клан и верховую езду; именованные сохранения не переписываются.
Чтобы сохранить отдельную новую версию, после обновления нажмите
«Сохранить текущий» и задайте другое имя. Новая ссылка содержит новую ревизию.

Если предмет исчез, изменились требования класса/расы или стало меньше
слотов под уже вставленные Souls, обновление отклоняется. Ничего автоматически
не снимается. Измените снаряжение осознанно либо оставьте старую ревизию.
Если старое автосохранение требует недоступный каталог, кнопка его не заменяет:
нужно восстановить доступ к этой ревизии или явно загрузить другой допустимый билд.
Закрытие «Билды» и изменение персонажа/ссылки отменяют ожидающий ответ обновления.

Ошибка автосохранения после успешного обновления не означает сохранённый новый
билд. Экспортируйте код перед выходом: прежнее автосохранение остаётся в браузере.
Если не удалось подтвердить восстановление после ошибки расчёта, автосохранение
приостанавливается; перезагрузите страницу для чтения прежнего сохранения.
Успешный явный импорт, загрузка именованного билда и обновление каталога удаляют
старую ссылку `#build=` из адреса. При перезагрузке она уже не подменит новый билд.

## Первый запуск и безопасный повтор

Команды разработчика из корня проекта: `npm run test:admin`,
`npm run admin:check`, `npm run admin:migrate`, `npm run admin:deploy`,
`npm run admin:seed`.

Seed запрещает повторное создание, если аккаунт, личный файл или pepper уже
существуют. Нельзя обходить это удалением настоящего аккаунта или заменой
секрета: существующий пароль зависит от pepper.

Если создание прервалось **до** установки pepper и записи аккаунта, флаг
`--resume-uninitialized` разрешает сохранить уже выданный личный пароль и
досоздать хеш/pepper. Он работает только при пустой таблице `admins` и
отсутствии `AUTH_PEPPER`. Если pepper уже установлен, этот путь запрещён.
Временный SQL-файл в личном каталоге содержит только соль/хеш и позволяет
закончить прервавшуюся запись без смены pepper. Его нельзя публиковать.

Wrangler может запрещать `secret put`, если загружена ещё не активированная
версия Worker. Сначала активируйте проверенный backend (без секретов он
отказывает во входе), затем выполните seed. Не активируйте диагностический
KDF-пробник вместо настоящего backend.

## Обновления

GitHub workflow `Cloudflare Admin API` проверяет backend на PR; после merge
в `bonaqu_projects` применяет миграции и публикует Worker. Используются уже
настроенные `secrets.CLOUDFLARE_API_TOKEN` и `vars.CLOUDFLARE_ACCOUNT_ID`.
Pepper не передаётся через GitHub: Wrangler сохраняет Cloudflare Secrets.
Пароли/куки/токены не логируются, bootstrap отключает запись дисковых логов CLI.

При потере доступа не меняйте секрет наугад. Сначала проверьте лимит попыток,
срок сессии, правильный домен и наличие личного файла. Сброс пароля и rotation
pepper требуют отдельной безопасной процедуры с отзывом всех сессий.
