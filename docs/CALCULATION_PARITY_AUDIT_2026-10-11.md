# Проверка игровых расчётов по Pandora Saga OS — 2026-10-11

**Статус:** обнаружено расхождение источников коэффициентов; соответствие всех итоговых чисел игре **не доказано**. Это технический диагностический документ, не пользовательский changelog.

## Проверенные первоисточники

- Публичный справочник текущего сервера: https://pandorasaga-os.com/gamedata/classes.json (28 классов).
- Публичный калькулятор текущего сервера: https://pandorasaga-os.com/#calculator .
- Сохранённый движок этого проекта: `js/ini.js` (28 массивов `Status['Mod']`) и `js/calc.js` (операторы округления).
- Датированный снимок только 28×HP/MP-коэффициентов хранится в `tests/fixtures/pandora-os-classes-20261011.json` для офлайн-повторения сравнения. Не считать его постоянно актуальным; свежесть подтверждается отдельной живой загрузкой.
- Современный интерфейс сохраняет Legacy-движок, поэтому успешное сравнение Modern ↔ Legacy не доказывает соответствие Pandora Saga OS.

## Результат первичного коэффициентного аудита

Все **28** текущих записей классов на сервере и **28** записей Legacy успешно сопоставлены по известному фиксированному порядку классов. У всех 28 обнаружено отличие хотя бы в одном базовом HP/MP коэффициенте. Пример для Warrior:

| Поле | Legacy `Status['Mod'][0]` | Pandora Saga OS `classes.json` |
| --- | ---: | ---: |
| HP base | 98 | 100 |
| HP per level, до округления | 100 / 5.847 ≈ 17.103 | 17.1 |
| HP per STA, до округления | 100 / 15.5 ≈ 6.452 | 6.45 |
| MP base | 16 | 30 |
| MP per level, до округления | 100 / 44.55 ≈ 2.245 | 2.24 |
| MP per SPR, до округления | 100 / 48.3 ≈ 2.070 | 2.08 |

**Важно:** вычисление `100 / x` — лишь перевод коэффициентов Legacy в сопоставимые единицы, а не новая формула для клиента. Legacy использует несколько операций `Math.ceil`, и результаты зависят от их **порядка**. Серверный JSON сообщает коэффициенты, но не гарантирует точный порядок округления итоговых значений клиента или самой игры.

Уже в данных есть не только малые расхождения после округления: например, MP base Warrior 16 против 30, CLERIC MP base 235 против 255. Править одни числа без доказательства полной формулы нельзя.

На публичной странице калькулятора при загрузке 11 октября 2026 года наблюдались Level 45, исходные STA/STR/AGI/DEX/SPI/INT 7/8/4/6/4/5 и HP 1643 / MP 163. Эта пара точно соответствует **округлению** выражений по коэффициентам `GLADIATOR` из того же справочника: `150 + 45×31.35 + 7×11.82 = 1643.49`, `30 + 45×2.73 + 4×2.53 = 162.97`. **Это не подтверждает активный класс калькулятора:** HTML-список доступных вариантов сам по себе не показывает значение JS-свойства `select.value`. Нельзя использовать этот один экран как эталон Warrior или утверждать, что серверный калькулятор ошибается.

## Воспроизводимая процедура

1. Запустить `node scripts/audit_pandora_os_class_coefficients.mjs --json > class-audit.json`. Скрипт **только читает** `js/ini.js` и публичный источник, не обновляет D1, не изменяет билды.
2. Для воспроизводимости сохранить оригинальный `classes.json` и запускать `node scripts/audit_pandora_os_class_coefficients.mjs --source classes.json --json`. Данные зафиксировать с датой и хешем перед любыми правками.
3. Для живой оценки итоговых показателей записать `select.value` рас/классов; сравнивать одинаковые уровень, STA/SPR, расовую пассивку, экипировку/заточку/души, баффы и гильдию на обеих страницах; отдельно фиксировать режимы без бонусов и с бонусами.
4. Пройти матрицу 28 классов на уровнях 1/10/20/30/40/45 и с независимыми STA/SPR. Отдельно проверить десятичные пороги и округления; не подменять их одним линейным приближением.
5. После получения доказанного полного правила корректировать только Modern-слой или одобренный версионированный расчётный модуль, оставляя музейный Legacy неизменным, с тестами эталонных векторов и проверкой старых билдов.
6. Бонусы предметов, расы, навыков, урона, скоростей, попадания и защиты требуют **отдельной** сверки. Нельзя заявлять полную игровую точность на основании HP/MP.

## Тесты и дальнейшие действия

`node --test tests/tools/pandora-os-class-coefficients.test.mjs` использует только синтетические записи и работает в CI без сети. Он проверяет корректность сравнения и обработку ошибок, **а не сходство чисел с игрой**.

Если живой сервер будет недоступен, инструмент должен выдавать ошибку, а не считать сохранённый устаревший снимок свежим. Никаких автоматических публикаций в D1 и массовых коррекций коэффициентов по этой диагностике нет.

Админка D1 остаётся редактором **текстов, локализаций и разрешённых данных каталога**, а не источником неподтверждённых формул; изменения формул должны проходить отдельно с доказательной базой и регрессиями. Составления корректного экрана сравнения с игровым персонажем пока нет; для проверки замечаний двух тестеров нужны векторы значений из актуального клиента игры.


## Проверена реализация формулы в публичном JavaScript калькулятора

Датированный URL клиентской сборки Pandora Saga OS: https://pandorasaga-os.com/assets/BuildCalculator-BiybySwQ.js (проверен 2026-10-11). Это **код текущего публичного калькулятора**, а не доказательство точного серверного расчёта всех боевых эффектов.

Из его функции `ga()` подтверждено:

```js
hpBase = roundHalfToEven(totalVIT * cls.hp.vit + level * cls.hp.lv + cls.hp.base) + maxLifeConst;
mpBase = roundHalfToEven(totalSPI * cls.mp.spi + level * cls.mp.lv + cls.mp.base) + maxManaConst;
```

Где `totalVIT`/`totalSPI` получаются из исходных значений расы, начального класса, распределения очков и применённых способностей. `roundHalfToEven` выбирает **чётное целое при точном результате x.5**, в отличие от `Math.ceil` и обычного `Math.round` JavaScript. Дополнительные `maxLifeConst/maxManaConst` применяются **после округления**.

Контрольный вектор из публичного калькулятора для Gladiator при Level 45, VIT 7, SPI 4: **HP 1643, MP 163**. Warrior при тех же входных данных даёт **HP 915, MP 139** согласно прямой формуле справочника. Второе значение не было непосредственно подтверждено в интерактивной форме.

Теперь есть воспроизводимый `scripts/reference_os_hpmp.mjs` и тест `tests/tools/reference_os_hpmp.test.mjs`: 28 классов × 6 уровней × 5 пар характеристик, отдельно проверено округление. Оба инструмента **только сравнивают** значения, не затрагивают старые билды.

Прежде чем подключать эту формулу к Modern, остаётся проверка соответствия `totalVIT/totalSPI` эффектам предметов, рас, гильдии и пассивных умений в **обоих** калькуляторах. Прямо записать новые коэффициенты в старый `Status.Mod` нельзя: сохранённая `Calc('LP'/'MP')` применяет дополнительный `Math.ceil` к каждому множителю и дала бы заведомо иной итог. Тесты игры с разными баффами и контрольными значениями ещё необходимы.

Аналогично, в исходном движке `Calc('RangeMelee')` и `Calc('RangeRange')` сейчас буквально записывают `'---'` в результат, хотя предварительно суммируют часть бонусов. Справочник Pandora Saga OS содержит параметр диапазона конкретного оружия и функции эффективности на расстоянии, но это **не** означает, что обе величины имеют те же единицы измерения и тот же набор модификаторов. Вывод произвольного числа вместо `---` до сверки был бы фиктивным.
