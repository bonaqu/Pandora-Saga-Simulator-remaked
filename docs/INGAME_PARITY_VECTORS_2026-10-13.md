В игровом клиенте эльф-воин 1 уровня со «Стойкостью разума» показал **149 ОЗ / 44 ОМ**. Снять эту устаревшую запись как «баг текущих коэффициентов»: игровой тест доказывает обратное.

Исходная расово-классовая матрица `js/ini.js` **совпадает с фактическими стартовыми атрибутами персонажа**: для ELF `[3,3,6,4,7,7]` плюс старт WARRIOR `[+2,+3,-1,+1,-1,0]` = **[5,6,5,5,6,7]**. Это подтверждает старые *стартовые атрибуты* для конкретной пары, но **не подтверждает** устаревшие коэффициенты Legacy.

Коэффициенты актуального сервера из `tests/fixtures/pandora-os-classes-20261011.json`:
- HP WARRIOR: `base=100`, `lv=17.1`, `vit=6.45`. `floor(100 + 1×17.1 + 5×6.45) = floor(149.35) = 149` — **точно игра**.
- MP WARRIOR: `base=30`, `lv=2.24`, `spi=2.08`. `floor(30 + 1×2.24 + 6×2.08) = floor(44.72) = 44` — **точно игра**. Публичный `halfEven` выдал бы 45, поэтому этот случай различает политики округления.

- «Rest POT» восстанавливает, по его сообщению, **около 3 880 ОЗ**.
- Уровень 45, класс Паладин, ВЫН 101, навык увеличения лечения, ближний бой 101, три вставленные «Души зелий» (по серверному источнику `103018`, `EP_MASTERY_POTION +8` на душу).

Условный контроль восстановления (только если **10 778 — максимальные ОЗ именно в момент применения зелья**):

```
floor(10778 * 15% * 240%) = 3880
```

Это точное совпадение, но не доказанный POT. Сохранённая арифметика Legacy при **итоговых STA 101**, `101` ближнего боя (при срабатывании пассивки) и **трёх действующих** душах `+8` даёт условный `POT=100+floor(101*101/500)+100+24=244`. Тогда для `LP=10778` получается `floor(10778*3660/10000)=3944`, то есть **на 64 больше** описанного восстановления. Нельзя считать это установленной ошибкой до проверки, что зелье выпито с тем же бафом, что все три души засчитались, `101 ВЫН` — итог после вещей, срабатывала именно эта пассивка и не было ограничения восстановления до текущего максимума.

Вещи с его слов: Кристальный меч +4, Рыцарский рунный щит +5/Душа льда, Прочный шлем +5, Сиреневое астирское платье +4/три Души зелий, Славные рукавицы +5 Свет/Звериная душа, Сапоги жизненной силы +5 Свет, Золотой плащ, две Украшения с кристаллами, Пояс чародея с двумя Душами желания, Амулет Ожерелье, Кольцо с кристаллом. Состав/заточка/души не полностью подтверждены ID каждого предмета. Пользователь сообщил также **7 895 ОЗ без экипировки** — это отдельная конфигурация, не путать её с 9 317 ОЗ «без бафа, но в вещах».

### Паладин — дополнительная независимая проверка бафа

Из текущих классовых коэффициентов PALADIN HP base=400, lv=70, vit=44.8: 45 уровень, итоговая ВЫН 101, halfEven(400+45×70+101×44.8) = **8075**. Прирост по кандидату 250 + floor(8075×0.15) = **1461**, точно равен независимому показанию 10778−9317. Если применить floor к классовой базе, получится 8074 и такой же прирост 1461. По одному бафу тип округления всей классовой базы пока не подтверждён.

Гипотеза (не факт): без вещей ВЫН 97 → floor(400+45×70+97×44.8)=7895, halfEven(...)=7896. Игрок действительно сообщил 7895 ОЗ без предметов, **но голую ВЫН 97 не сообщал**. Поэтому на основании этого числа преждевременно менять весь Modern на floor.

**Исправлено последующим ручным игровым тестом (раздел 1):** эльф-воин уровня 1 в реальном клиенте показывает **149 ОЗ / 44 ОМ**, и это точно совпадает с новой серверной формулой при подтверждённых ВЫН5/СД6 и округлении вниз. Старые 139/45 были числом из публичного веб-калькулятора, **не игрового клиента**. Прежний контрпример опровергнут; результаты Паладина остаются недостаточно параметризованными.

Повторяемый источник-входной аудит выполняет scripts/audit_pandora_os_cleric_parity.mjs, тест tests/tools/pandora-os-cleric-parity.test.mjs. Режим --live GET-only запрашивает classes.json/items.json/souls.json/skills.json, проверяет **две** актуальные записи «Знака жизни» и при недоступности прекращает работу без подмены датированным снимком. Реальные механики в Modern не изменяются до устранения контрпримеров и подтверждения игровых условий.
