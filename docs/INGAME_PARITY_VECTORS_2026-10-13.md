# Игровые эталоны для проверки Modern — 13 октября 2026

От пользователя получены показания из **фактического актуального игрового клиента Pandora Saga OS**, а также эталон с публичного калькулятора сервера. Это наблюдения, а не доказательство универсальных формул. Нельзя механически перезаписывать значения классов, HP/MP, слоты душ или D1 на основании одного билда.

## 1. Эльф — Воин — уровень 1, без вещей

Указанный пользователем общий билд публичного игрового калькулятора: ELF / WARRIOR / level 1 / без распределённых очков / расовая пассивка `900020003` («Стойкость разума»).

| Источник | Максимальные ОЗ | Максимальные ОМ |
| --- | ---: | ---: |
| Публичный калькулятор актуального сервера, со слов пользователя | **139** | **45** |
| Наш Legacy/Modern до исправления | **151** | **37** |

**Строго воспроизводимая причина нашего числа:** в сохранённом `js/ini.js` эльф стартует с `STA=3`, `SPR=7`; воинская ветка добавляет `STA+2`, `SPR−1`, получаем 5 и 6. В `js/calc.js` исторический расчёт:

```
HP=98+ceil(1*(100/5.847))+ceil(5*ceil(100/15.5))=151
MP=16+ceil(1*(100/44.55))+ceil(6*ceil(100/48.3))=37
```

Текущие серверные коэффициенты Warrior из `classes.json`: HP `base=100,lv=17.1,vit=6.45`; MP `base=30,lv=2.24,spi=2.08`. Обновлённый публичный калькулятор отдельно применяет свои базовые/расовые атрибуты и `halfToEven` округление. **Подставлять свежие коэффициенты в старый вложенный `ceil` нельзя.** `races.json` у игры возвращает HTTP 404; живого серверного справочника базовых характеристик рас по этому адресу нет. Поэтому точный алгоритм текущей сборки (включая возможные ранние плоские модификаторы) остаётся недоказанным. Не выдавать `149` (старые STA=5 с коэффициентами сервера) за подтверждённые `139`.

```

```

Это точное совпадение, но не доказанный POT. Сохранённая арифметика Legacy при **итоговых STA 101**, `101` ближнего боя (при срабатывании пассивки) и **трёх действующих** душах `+8` даёт условный `POT=100+floor(101*101/500)+100+24=244`. Тогда для `LP=10778` получается `floor(10778*3660/10000)=3944`, то есть **на 64 больше** описанного восстановления. Нельзя считать это установленной ошибкой до проверки, что зелье выпито с тем же бафом, что все три души засчитались, `101 ВЫН` — итог после вещей, срабатывала именно эта пассивка и не было ограничения восстановления до текущего максимума.

### Паладин — дополнительная независимая проверка бафа

Из текущих классовых коэффициентов PALADIN HP base=400, lv=70, vit=44.8: 45 уровень, итоговая ВЫН 101, halfEven(400+45×70+101×44.8) = **8075**. Прирост по кандидату 250 + floor(8075×0.15) = **1461**, точно равен независимому показанию 10778−9317. Если применить floor к классовой базе, получится 8074 и такой же прирост 1461. По одному бафу тип округления всей классовой базы пока не подтверждён.

Гипотеза (не факт): без вещей ВЫН 97 → floor(400+45×70+97×44.8)=7895, halfEven(...)=7896. Игрок действительно сообщил 7895 ОЗ без предметов, **но голую ВЫН 97 не сообщал**. Поэтому на основании этого числа преждевременно менять весь Modern на floor.

Второй контрпример: Эльф Воин уровня 1 при *историческом* старте ВЫН5 / СД6 по новым классовым коэффициентам получает **149 ОЗ и 45 ОМ**, а игровой калькулятор пользователя показывает **139 ОЗ и 45 ОМ**. Нужна актуальная база расы или другой подтверждённый модификатор; слепое применение одной классовой формулы ко всем расам даст ошибку 10 ОЗ.

Повторяемый источник-входной аудит выполняет scripts/audit_pandora_os_cleric_parity.mjs, тест tests/tools/pandora-os-cleric-parity.test.mjs. Режим --live GET-only запрашивает classes.json/items.json/souls.json/skills.json, проверяет **две** актуальные записи «Знака жизни» и при недоступности прекращает работу без подмены датированным снимком. Реальные механики в Modern не изменяются до устранения контрпримеров и подтверждения игровых условий.
