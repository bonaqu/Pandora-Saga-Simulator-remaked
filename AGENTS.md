# Правила релизов и журнала изменений

- Источник истории — `CHANGELOG.md`. Для выпуска добавляй новую первую запись с заголовком `## Modern X.Y — название, YYYY-MM-DD`; сначала проверяй последнюю версию в ветке `bonaqu_projects`. Не переписывай старые релизы.
- Для заметных игроку изменений используй `release-notes:user:ru` и `release-notes:user:en`; для разработки, админки, API, D1, миграций, диагностики, CI и тестов — `admin-notes:ru` и `admin-notes:en`. Не выдавай техническую работу за новое игровое содержание. Заголовок и все поля публичного release payload должны быть безопасными для игроков и соответствовать фактическому выпуску.
- Чисто технический выпуск содержит только административные блоки на двух языках: существующий сборщик показывает нейтральное сообщение, не повторяя старые игровые новости.
- После изменения `CHANGELOG.md` выполни `python scripts/sync_localized_changelogs.py` и `python scripts/sync_localized_changelogs.py --check`. Не редактируй локализованные журналы как независимые источники.
- Перед выпуском проверь согласованность версии, содержимого журнала, собранных `modern/version.js`, `modern/version.json`, полного объекта в `modern/release-notes.js` и окна «Что нового» на RU/EN. Используй соответствующие тесты сборки и интерфейса; проверяй также технический выпуск, историю и отсутствие внутренних подробностей в публичных данных.
- Legacy остаётся версией 2.00. Версия Modern и ревизия каталога D1 независимы: публикация каталога сама по себе не требует повышения версии UI. Не записывай невыпущенные изменения как опубликованные.
